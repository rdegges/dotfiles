# Tester agent evals

Regression evals for the `tester` agent (`~/.claude/agents/tester.md`). Run
after any change to the tester's definition; compare against the results
table before merging the change.

## Fixture: tipsy

`tipsy/` is a small vanilla-JS tip calculator seeded with 12 known defects
(4 logic bugs, 3 weak tests, 5 visual/UX issues). Ground truth and scoring
rules live in `tipsy-seeds.md`. The fixture is the PRISTINE pre-tester state
— never commit tester output back into it.

### Protocol

1. Copy the fixture to a scratch dir (never run in place):
   `cp -R ~/.claude/evals/tester/tipsy /tmp/tipsy-eval && cd /tmp/tipsy-eval && git init -q && git add -A && git commit -qm "generate tipsy tip calculator app"`
2. Spawn the `tester` agent with this brief (verbatim, adjusting the path):

   > Repo: /tmp/tipsy-eval (local git repo, single commit, no remote).
   > The change under test: the entire app — it was just generated by a maker
   > agent in one pass (vanilla JS tip calculator: src/tip.js logic module,
   > app.js DOM wiring, index.html, style.css, server.js static server,
   > node:test suite in test/). Nothing has been reviewed yet; you are the
   > first gate. Run your full process per your definition. Notes: `npm test`
   > runs the suite (no dependencies to install). `npm start` serves the app
   > at http://localhost:4173 — the change is user-facing, so the visual/UX
   > pass applies; use the browse skill for screenshots. Do not deploy
   > anything or touch files outside this repo. This is a host-run scratch
   > project — no Docker convention exists here.

   Do NOT mention the seeds or this eval in the brief.
3. Score the report against `tipsy-seeds.md`: binary CAUGHT/MISSED per seed.
4. Append a row to the results table. A previously-caught seed that is
   MISSED triggers one immediate re-run. Missed twice consecutively =
   regression = REVISE on the tester change. Caught on re-run = run
   variance; record both rows.

## Known limits

- The fixture cannot exercise the before/after visual comparison path (it is
  a single-commit repo with no prior UI). A second fixture with a base UI +
  regressing diff would cover it.
- Visual seed detection depends on the gstack `browse` skill being installed.
